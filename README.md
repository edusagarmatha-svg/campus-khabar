# Campus Kabar

Campus Kabar is a campus news and publishing platform: a public news portal plus a staff editorial console for news, articles, notices, announcements, multimedia, and an approval workflow.

## Architecture

```
Browser
  │
  ├── React 19 + Vite public portal and /admin staff console
  │       │  same-origin /api requests
  │       ▼
  └── Express 5 API
          ├── JWT access tokens (in memory) + rotating refresh cookie
          ├── Zod validation and role checks
          ├── Knex query builder
          └── MySQL 8
                  │
                  └── Cloudinary (signed direct browser uploads)
```

- The frontend never connects to MySQL directly.
- Access tokens are returned in JSON and kept in memory; refresh tokens are HttpOnly, Secure in production, rotated on every use, and stored only as SHA-256 hashes.
- Media bytes go directly from the browser to Cloudinary. The API signs uploads and verifies uploaded metadata through the Cloudinary Admin API.
- `robots.txt` and `sitemap.xml` are generated by the API from published, non-deleted, non-expired content.

## Prerequisites

- Node.js 22.23.x (the project is tested on Node 22.23.4)
- MySQL 8
- A Cloudinary account for media uploads
- A reverse proxy such as Nginx or Caddy for production TLS and static hosting

## Local setup

### 1. Backend

```bash
cd backend
npm ci
cp .env.example .env
chmod 600 .env
```

Fill in `DB_*`, `JWT_ACCESS_SECRET`, `PUBLIC_SITE_URL`, and the Cloudinary values. Generate a JWT secret with:

```bash
node -e "console.log(require('crypto').randomBytes(48).toString('base64url'))"
```

Create the database and run migrations:

```bash
mysql -uroot -p -e "CREATE DATABASE campus_kabar CHARACTER SET utf8mb4 COLLATE utf8mb4_0900_ai_ci"
npm run migrate
npm run seed
npm run create-admin
npm run dev
```

The API listens on `http://localhost:4000` by default.

### 2. Frontend

```bash
cd frontend
npm ci
cp .env.example .env.local
npm run dev
```

Set `VITE_PUBLIC_SITE_URL` to the public origin used for canonical URLs and social metadata. The Vite dev server proxies `/api` to `http://localhost:4000`.

## Production configuration

At minimum, production must set:

- `NODE_ENV=production`
- `PUBLIC_SITE_URL=https://news.example.com` (HTTPS, no trailing slash)
- `CORS_ORIGIN=https://news.example.com`
- `TRUST_PROXY=true` or the exact proxy hop count when behind a load balancer
- `DB_SSL=true` when `DB_HOST` is not localhost, with `DB_SSL_CA` if the provider requires a private CA
- `JWT_ACCESS_SECRET` of at least 32 characters
- `COOKIE_SECURE=true`; production refuses to start if this is false
- Cloudinary credentials

The backend also refuses to start in production when a remote database is configured without TLS, when `PUBLIC_SITE_URL` is not HTTPS, or when a rate-limit value is invalid.

Never commit `.env` files. Keep the backend `.env` at mode `600`; production refuses to start if the file is group- or world-accessible.

### Deployment shape

A typical deployment has:

1. A static host/reverse proxy serving `frontend/dist`.
2. The same origin proxying `/api/*`, `/sitemap.xml`, and `/robots.txt` to the Express API.
3. An SPA fallback from unknown frontend paths to `frontend/dist/index.html`.
4. TLS termination at the proxy, with `TRUST_PROXY` configured so rate limiting sees real client IPs.
5. Long-lived cache headers for hashed `/assets/*`; short-lived or no-cache headers for HTML.

The API does not serve the frontend bundle itself.

## Admin operations

- Use `npm run create-admin` only for the first Admin. It is interactive and refuses to create a second Admin.
- Use `npm run reset-admin-password` to recover an existing Admin. It updates the password hash and revokes that account's active sessions.
- Follow [`docs/ADMIN_RECOVERY.md`](docs/ADMIN_RECOVERY.md) for the full recovery procedure.

## Verification

```bash
cd backend
npm test        # requires a dedicated campus_kabar_test database on port 3308
find src -name '*.js' -print0 | xargs -0 -n1 node --check

cd ../frontend
npm run lint
npm run build
```

The backend suite intentionally refuses to run against the normal development database. See the test files for the required `campus_kabar_test` / port `3308` setup.

## SEO

- Canonical and Open Graph URLs use `VITE_PUBLIC_SITE_URL` on the frontend and `PUBLIC_SITE_URL` on the API.
- `GET /robots.txt` points crawlers at `GET /sitemap.xml`.
- The sitemap excludes drafts, pending review, changes requested, unpublished, deleted, expired, and future-dated content.
- News posts emit `NewsArticle` JSON-LD; other posts emit `Article` JSON-LD.
- The public layout emits `Organization` and `WebSite` JSON-LD.
